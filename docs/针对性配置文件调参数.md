# ETH 多头参数优化建议(基于回测成交过程分析)

- 日期:2026-10-02
- 依据:regime_1x 网格 15 个 ETH 回测(5 行情状态 × 3 方向,2019-11-27 ~ 2026-10-01
  全历史,本地 Binance USDT-M 1m K 线)的成交明细(`fills.csv`,约 10 万笔)。
- 配套材料:
  - 回测结果汇总:`backtests/regime_analysis_2026-10/regime1x/summary_tables.md`
  - 成交过程统计:`backtests/regime_analysis_2026-10/regime1x/eth_fills_stats.json`
  - 分析脚本:`backtests/regime_analysis_2026-10/regime1x/analyze_eth_fills.py`
  - 完整报告:`backtests/regime_analysis_2026-10/REPORT.md` 第 7、8 节
- 性质:私有分析产物,不入库公开。

## 1. 成交过程揭示的四个事实

1. **已实现亏损几乎 100% 来自自动解套(unstuck)**。五个多头配置中,解套平仓亏损
   占总亏损 90~99%(normal_osc:总亏损 -37.4 万,解套 -36.8 万;low_vol_osc:
   -116.0 万中 -115.1 万)。网格止盈全部盈利,TWEL 执行器成本可忽略(<0.1%)。
   解套是唯一有效的亏损通道,也是唯一值得调的亏损侧参数面。
2. **解套行为是"深位滞留后等反弹"**。解套触发时仓位暴露中位数 ≈ 0.98×TWEL
   (资格线 0.833×WEL,价格还需回到 EMA 带附近才成交)——仓位先堆满、再等反弹、
   然后小切片多次割肉。解套成交占全部成交的比例:low_vol_osc 50%、strong_trend 42%、
   normal_osc 34%、bear 15%、extreme_vol 0.8%,与 DCA 链条深度(平均 8.1 / 2.7 /
   3.7 / 2.0 / 1.4 层)完全正相关。
3. **暴露上限持续打满、补仓被大量裁剪**。震荡/趋势多头档 WE 最高触及 0.99×TWEL;
   补仓被 WEL 裁剪的比例:low_vol_osc 22.5%、normal_osc 15.3%、bear 4.0%、
   strong_trend 0%、extreme_vol 0.4%。低波动档的初始仓位(4.5%)相对间距(1.37%)过大。
4. **实际止盈距离由波动率权重主导**。配置的止盈 base 仅 0.25%~1.06%,实际成交
   中位距离 1.30%~1.87%,差值来自 `threshold_volatility_1h_weight`(≈1.0)的动态抬升。
   调整 base 的边际效果弱,权重才是主控旋钮。

## 2. ETH 多头参数优化建议(按行情状态)

| 状态 | 参数 | 现值 | 建议 | 依据 |
|---|---|---|---|---|
| normal_osc | unstuck.threshold | 0.833 | **0.72** | 解套提前到 0.72×WEL,减少 0.98 处滞留 |
| normal_osc | unstuck.close_pct | 0.936% | **1.4%** | 切片加大,减少割肉次数 |
| normal_osc | entry.initial_qty_pct | 3.13% | **2.6%** | 补仓裁剪 15% → 目标 <8% |
| low_vol_osc | entry.initial_qty_pct | 4.5% | **3.0%** | 裁剪 22.5% 不可接受 |
| low_vol_osc | entry.threshold_base_pct | 1.37% | **1.7%** | 链条从 8.1 层压到 ~5 层 |
| low_vol_osc | entry.double_down_factor | 0.78 | **0.72** | 减缓中段堆量 |
| low_vol_osc | unstuck.threshold | 0.88 | **0.75** | 50% 解套占比必须降 |
| low_vol_osc | unstuck.close_pct | 0.7% | **1.2%** | 同上 |
| strong_trend | close.threshold_base_pct | 0.77% | **1.0%** | 让利润奔跑(与窗口法结论同向) |
| strong_trend | unstuck.threshold | 0.85 | **0.75** | 解套亏损占 93%,提前减仓 |
| bear | we_excess_allowance_pct | 0.8 | **1.0** | 唯一轻微顶格的档(裁剪 4%),其余健康 |
| extreme_vol | twel | 0.5 | **0.65** | WE 顶格 0.495、adg 仅 0.03%,资本闲置 |
| extreme_vol | entry.initial_qty_pct | 0.93% | **1.2%** | 同上;间距 9.1% 与 dd 0.25 余量充足,保持 |

**明确不动的参数**:

- 各档 close 的波动率权重(实际止盈距离 1.3~1.9% 与成交密度匹配良好);
- extreme_vol 的 entry threshold(9.08% + 动态项,是该档生存性的来源);
- bear / extreme_vol 的解套参数(占比 15% / 0.8%,健康)。

## 3. 空头与双向的结论(反向参照)

- 全历史窗口不适用于空头:short/both 30 个配置中 26 个清算,其成交统计只反映
  清算前的路径,不能作为调参依据。
- both 模式的结构性问题:空头仓位使亏损预算被共享消耗,多头解套占比从单边 34%
  骤降到 10%(解套被预算饥饿抑制),账户反而更快被空头皮掉。
  空头必须由状态开关控制,或以显著更低的 TWEL 独立核算。
- 空头参数的验证窗口:仅在 bear / normal_osc 状态窗口内重跑后再调。

## 4. 验证路径与验收标准

1. 按第 2 节表格生成 ETH 5 状态的 v2 参数集;建议只改表中列出的参数,
   单变量(或成对)验证,避免同时改动多个归因。
2. 用同一本地数据源重跑全历史多头 5 档,验收标准:
   - unstuck 亏损占比 < 80%;
   - 补仓裁剪(crop)< 8%;
   - adg_pnl 不低于现值;
   - drawdown_worst_usd 不深于现值 + 5%。
3. 通过后进入多币组合回测(处理 WEL 分母与选币器),
   再用优化器在各状态窗口内精调。

## 5. 口径说明

单币回测下 `backtest.dynamic_wel_by_tradability=true` 使有效 WEL = TWEL;
多币组合下 WEL = TWEL / n_positions。本文件中的阈值/比例类建议
(unstuck.threshold、close_pct、double_down_factor 等)可直接迁移;
暴露类数值(TWEL、initial_qty_pct、we_excess_allowance_pct)
需在组合语境下重新标定后再采用。

### 6.4 空头侧与多头侧结论的差异

- 多头侧的"解套提前 + 加大切片"在空头密集档(low_vol_osc)同样有效,
  且改善幅度更大(回撤 -68%)——链深修正与方向无关。
- 空头侧多出一个多头没有的失败模式:**方向逆风窗口**(normal_osc 含上升段)
  无法用入场/解套参数修复,只能靠暴露控制(TWEL)或状态开关。
  这也再次印证第 3 节:空头必须独立核算、独立开关。
- bear 档空头的基线(解套 threshold 0.85、excess 1.04)已经接近最优,
  不需要镜像多头的全部修改——参数修正只对"链条被推深"的档位有效。
